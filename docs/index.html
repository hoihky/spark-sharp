SparkSharp

SparkSharp is the companion repository for Spark: a stable C interop layer (SparkInterop), generated Spark.Bindings, the Spark.Scripting bootstrap, and an optional CoreCLR host (SparkScriptHost) that loads your game as a .NET 8 class library. The C++ engine keeps only SparkScriptBind.hpp annotation macros; everything else lives here.

Overview

Managed games are not standalone executables in this stack: you ship a YourGame.dll plus runtimeconfig.json, and the native SparkScriptHost loads CoreCLR via hostfxr, calls your GameEntry.Initialize, and registers Spark.Scripting callbacks that drive the same IGame loop as C++ titles. Component APIs are mirrored from engine headers using SPARK_SCRIPT_BIND and ClangSharp codegen.

Stable C ABI

SparkInterop exports spark_* functions backed by SparkEngine + SparkGameplay types.

Generated bindings

Spark.Bindings — P/Invoke, FromInterop component mirrors, GameObject accessors.

Thin SDK

Spark.Scripting — ScriptHostEntry, GameBootstrap, SparkGame base class.

Sibling engine

Configure with SPARK_ENGINE_ROOT pointing at the Spark C++ checkout (assets, headers, CMake target).

  • CoreCLR / hostfxr

Architecture

Native host owns the window, Vulkan renderer, and simulation loop; managed code implements gameplay through bindings.

Bindings pipeline

Regenerate after changing SPARK_SCRIPT_BIND in engine headers or SparkInterop.h in this repo:

export SPARK_ENGINE_ROOT=/path/to/spark
./tools/generate-csharp-bindings.sh

Python bindgen reads component headers from SPARK_ENGINE_ROOT; ClangSharp emits Native.g.cs; mirror codegen produces Components/FromInterop/*.g.cs. See the Spark engine doc Component script codegen for the full pipeline (paths refer to spark-sharp for tools and outputs).

Quick start

Requirements: CMake ≥ 3.28, C++23, Vulkan SDK (same as Spark), .NET 8 SDK, sibling spark checkout or SPARK_ENGINE_ROOT.

cmake --preset debug
cmake --build build --target SparkInterop SparkScriptHost SparkHelloCsGameDebug
cmake --build build --target SparkRunHelloCsGameDebug

SparkRunHelloCsGameDebug sets working directory to the engine repo so assets/ resolve. Override with SPARK_ENGINE_ROOT.

Debugging C#

Use SparkScriptHost (HelloCsGame Debug) in CLion or VS Code (.vscode/launch.json): native LLDB on the host, then attach a .NET debugger for breakpoints in HelloGame.cs. Shell shortcut: tools/clion-run-hello-cs-game-debug.sh.
